# monet-rn

monet for React Native: monet-core's `Client` over the platform's native
network stack, behind one Rust TurboModule (`Monet`).

| Platform | HTTP | WebSocket | Trust |
| --- | --- | --- | --- |
| iOS | URLSession | NWConnection (RFC 6455 frames) | system store |
| Android | hyper + h2 + rustls | tokio-tungstenite + rustls | platform verifier |

The repo's `crates/` is the **single source of truth** (host tests and the
conformance batteries run there). `vendor/` is the copy the consumer app's
aggregate build compiles.

## Development loop

```bash
# edit crates/monet-* in the repo, run the workspace tests there, then:
./scripts/sync-vendor.sh        # rsync crates -> vendor/ + regenerate the mirror workspace

# then build the demo app normally (the cargo build runs in the app's
# platform build via react-native-rust-turbo):
cd ../../platform/rn-demo && cd ios && pod install && xcodebuild ...   # iOS
cd ../../platform/rn-demo && cd android && ./gradlew assembleDebug    # Android
```

`vendor/` and `generated/` are gitignored: the first is regenerated by the
sync script, the second by the Rust macro at build time.

## Why the crate lives at the package root

The aggregate build (react-native-rust-turbo's `build.js`) resolves every
module crate from `node_modules/<package>/<crate>` with textual path joins,
so:

- the framework crates (`jsi`, `jsi-turbo`) are referenced as siblings in
  `node_modules` — this only works with the crate at the package root;
- the monet crates are referenced as `vendor/…` paths inside this package —
  path deps out of the package would resolve into the consumer app's
  directory and dangle.

The vendored crates keep their `x.workspace = true` inheritance: it resolves
against `vendor/Cargo.toml`, the mirror workspace the sync script generates
from the repo root's tables (with `[dev-dependencies]` stripped — the app
build never compiles tests, and the dev-deps point at crates that are not
vendored).
