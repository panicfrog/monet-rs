# monet v2：nitro 功能面对标 + hooks 深化

## Context

v1 轨道（monet-rn plan M0–M6）已完成：四端矩阵绿（模拟器/真机 × iOS/Android）、DESIGN.md 验证 IOU 清零、全部边界记录在案。v2 的范围就是那些"v1 明确不做"与"hooks v1 边界"的存量，加上工程收尾。本 plan 入库即 W0。

**范围定调（2026-11-10，用户确认）**：

- **permessage-deflate：永久非目标**。v1 双侧不支持、一致性绊线已钉（`unrequested_deflate_offer_round_trips`，见 2026-11-10 提交）；启用压缩需要 iOS 手写帧实现 deflate（维护成本不值得）且跨实现分帧风险高。绊线保留——它存在的意义恰是"不支持"这个契约本身：tungstenite 上游哪天实现了 RFC 6455 §4.1 第 5 步，检查先红，两端一起收紧，但**不**因此启用压缩。
- **monet-ws 换纯同步 tungstenite：不做**。私有单线程 runtime 藏得干净（调用方零 tokio 感知），无动机。
- monet-dart（flutter_rust_bridge）独立轨道，不在此 plan（core 不动原则下互不影响）。

## 已核实的关键事实（决定设计形状，2026-11-10）

1. **iOS 的 per-request 参数只差 core 层**：`UrlsessionTransport` 的 `follow_redirects`/`timeout_ms` 是实例级 builder 字段，但 Swift 控制面 `transport_start(id, url, method, followRedirects, timeoutMs)` **已按调用传参**——W1 只需要 core `Request` 的覆盖语义 + execute 读取优先级，Swift 侧零改动。
2. **Android 上传已是流式接口**：`MonetUploadProvider extends UploadDataProvider`（Cronet 的流式上传契约），现为字节数组适配器。流式上传 = provider 增量喂入 + 控制面加 body-chunk 命令，接口形态不变。
3. **core 的流式上传 Rust 侧已验证**：`body::channel` + conformance 的 `slow_upload_does_not_block_new_requests` 检查（M3 起）就是流式请求体——缺的只是 TS 层入口与 iOS Swift 数据面。
4. **背压的自然落点已存在**：monet-rn 的 fetch pump 是"信号 + 零拷贝拉取"（on_chunk 信号 + take_chunk 拉取）——拉取本身就是消费侧节奏；缺的是"JS 未取走时暂停 transport 读取"的阀门。iOS 数据面有原生原语：`URLSessionTask.suspend()/resume()`。
5. **mock 响应需要 trait 变体**（hooks plan 已记录）：request hook 是 Request→Request，造不出 Response。
6. **token refresh 的 shape 已存在**：M5 电池 `http:hook_retry_uses_new_token` 就是完整 token-refresh 场景（401 → response hook 刷新 → retry 出口 → 新 token 放行）。A2/W4 的第一步是评估"hook 组合子 vs 内置策略"，很可能结论是已有等价能力 + 文档对齐。

## 工作流

### W1：per-request timeout / redirect（core Request 加宽，地基项）

- **core**：`Request` 加 per-request 覆盖字段（`timeout_ms: Option<u64>`、`follow_redirects: Option<bool>`），builder 方法 `with_timeout_ms` / `with_redirect_policy`；`Client::execute` 的读取优先级：request 覆盖 > client/transport 默认。
- **transport 传透**：urlsession 直接可用（事实 1）；rustls 的 head 超时与 redirect 逻辑从 request 读；httpengine 的 Cronet 侧 per-request redirect（`setRedirectBehavior`）与 timeout（`UrlRequest.Builder` 的 timeout 参数）核实后接。
- **monet-rn**：`fetch(url, {timeoutMs, redirect})` 透传进 FetchOptions；TS 类型加宽。
- **电池**：conformance 加 per-request 覆盖检查（client 级 500ms + request 覆盖 100ms → 按 100ms 失败；client 级 follow + request no-follow → 3xx 原样返回）；JS 电池镜像。

### W2：通道层一体设计——上传流式 + 响应背压

同一个 pump 的两个方向，一起设计一起落地：

- **上行（流式上传）**：
  - TS 层：`fetch(url, {body: AsyncIterable | ReadableStream, contentType})`——pump 逐块喂 core 的 channel body。
  - iOS Swift：`transport_set_body`（缓冲 Data）改为 `transport_body_chunk(id, data)` + `transport_body_complete(id)` 控制面命令（cxx 桥加宽，纯加法）；`URLRequest.httpBody` 改 `uploadTask(withStreamedRequest:)` 形态。
  - Android：`MonetUploadProvider` 从预缓冲改为增量读（队列喂入），`getLength()` 未知长度路径核实。
  - 电池：慢喂上传 + 并发不阻塞（Rust 侧已有 `slow_upload` 检查，JS 侧镜像——M3 时 JS 没有流式入口所以没有这条）。
- **下行（响应背压）**：
  - 语义对齐 nitro 的 `Promise<bool>`：JS 消费者逐块确认；未确认时 pump 暂停 transport 读取。
  - 形态：take_chunk 已是拉取；加"取走前不再读下一块"的 pump 阀门（rustls：body stream 的 poll 门控；urlsession：`task.suspend()/resume()`；httpengine：核实 Cronet 的读取暂停面）。
  - 电池：慢消费者（逐块 sleep 的 JS 循环）期间，服务器观察连接读取窗口不推进（`/held` 的反向版：服务器发送侧观察 TCP 背压）。
  - **设计先行**：水位语义（暂停粒度、恢复阈值、与 cancel 的交互）先写进本节再动代码。

### W3：mock 响应 + body 观察（hook 协议加宽，通道耦合项在 W2 之后）

- **mock 响应**：
  - core：`run_request_hooks` 返回值加宽为 `Modified(Request) | Mocked(Response)`（enum，或独立 `mock_request` 钩子位——设计时定）；mock 命中时 pump 直接构造 Response 走响应链——**observer 必须看到 mock 的最终形态**（M5 的"最终形态"语义延伸）。
  - monet-rn 回程协议：`resolveRequestHook(hookId, {mocked: {status, headers, body}})`——协议加宽，纯加法。
  - 电池：hook 返回 mock → fetch 收到（状态/头/body 精确）且**服务器零连接**（`/ws-open` 式的计数观察：mock 期间 plain 服务器连接数不变）。
- **body 观察（B2/B3 合并处理）**：request/response observer 的事件加 body 首块或全文（上限截断）；协议取舍（拷贝 vs 零拷贝、大小上限）设计时定。与 W2 的通道已耦合，故排后。

### W4：prefetch + token refresh 评估

- **prefetch**：先核实 nitro 语义（连接预热还是完整响应缓存），再定形态：
  - 连接预热：transport 层预建连接（rustls/hyper 连接池预热；URLSession 无直接 API，近似路径评估）。
  - 完整缓存：client 级 response store + fetch 命中语义（过期/失效策略）。
  - **设计先行**，两种形态工作量差异大，核实后在本节补记再动代码。
- **token refresh 评估**（A2）：对照 nitro 的内置行为逐项核对 M5 的 hook 组合子能力（刷新触发、并发请求共享刷新、失败传播），输出结论：内置策略（client 配置）或"组合子已覆盖 + 文档示例"。很可能零代码。

### W5：FormData / Blob + 内置重试 + WS 重连

- **FormData**：TS 层 multipart 组装（boundary、parts、文件 part 从 RN 的资产/blob 读）→ body bytes + content-type；core 不动。Blob bridge 视 RN 侧能力评估。
- **内置重试策略**：client 配置（`retries`, `backoff`，5xx/网络错误域）——与 hook 的 retry 出口共存（策略先判，hook 可否决）；电池：5xx 退避重试后成功 + 上限后失败。
- **WS 重连**：`MonetWebSocket` 的可选重连策略（退避、最大次数、重连后事件语义——`onreconnect` 事件加宽）；设计先行（upgrade 无 head，重连是纯连接层）。

### W6：工程收尾

- podspec `output_files` 上游修复合入（jsi-rs checkout 已备两行修复，待 review）。
- monet-cronet 遗留清理（DESIGN.md 记录的旧轨道）。
- （可选）vendor 新鲜度守卫：run 前对 `crates/` ↔ `vendor/` 做 rsync --dry-run 比对（Cargo.toml 的脚本改写排除在外），过时即拒编。
